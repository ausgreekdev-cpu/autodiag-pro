# Code review — AutoDiag Pro 0.23.0

**Scope:** whole repository (`autodiag/`, `tests/`, packaging, CI). 11,790 lines of app code,
9,339 lines of tests, 105 commits.
**Method:** static read of every core module, plus targeted experiments against the real
code (fault injection in the engine, decoder fuzzing, micro-benchmarks of the render and
serial hot paths). Measurements were taken on this machine with Qt's `offscreen` platform,
CPython 3.12. Numbers are indicative, not hardware-absolute.

## Baseline

| Check | Result |
|---|---|
| `ruff check .` | clean |
| `pytest -q` | **649 passed in 22.0 s** |
| Type checking | none configured |
| Coverage | none measured |

The suite is genuinely strong for a hardware project: scripted ELM327 fakes, contract-checked
decoder fuzzing, offscreen UI tests, and a test for almost every module. Nothing in this review
disputes the test discipline — the findings below are places where the tests cannot see the
problem (thread boundaries, real render cost, real serial timing) or where the architecture has
started to leak.

## TL;DR — the five things worth doing first

1. **One unexpected exception silently kills the polling thread** (`engine.py:133`). Verified by
   fault injection: the exception escapes `step()` → `run_forever()` returns → the `QThread`
   ends, the UI still says *Connected*, and no reconnect is scheduled.
2. **Long jobs are uncancellable**, so closing the window can destroy a running `QThread`
   (`main_window.py:432`, `engine.py:293`). Worst case is a Mode $06 / freeze-frame walk against
   a dead bus: dozens of 5 s timeouts, then `QThread: Destroyed while thread is still running`.
3. **The live graph is O(buffer) per sample** (`graph.py:116`). Measured 4.5× slowdown as the
   2,400-point buffer fills (1.20 → 5.40 ms per 6-PID batch). It does a full `setData` copy and a
   full y-range scan on every point.
4. **Every adapter command pays a fixed 30 ms drain** (`elm327.py:203`). Measured 30.1 ms per
   command against a port that behaves like real hardware — 12 % of the 250 ms poll budget per
   request, and paid three times for a UDS exchange.
5. **Reports mix time bases and pass user text into CSV unescaped** (`export.py:119`, `:181`).
   UDS rows are local naive time next to a UTC `generated_at`, and `=cmd|' /C calc'!A0` in a work
   order is written verbatim into the CSV.

## P0 — Correctness and robustness

### 1. Engine loop has no failure boundary

`ObdEngine._execute` (`autodiag/services/engine.py:133`) catches only `TransportError` and
`ElmError`:

```python
try:
    handler(payload)
except TransportError as exc: ...
except ElmError as exc:
    self._emit("error", str(exc))
```

Anything else (`ValueError`, `IndexError`, `TypeError`, a decoder bug on an unusual ECU payload)
propagates through `step()` and terminates `run_forever()`. Consequence: the worker thread ends
without emitting `disconnected`; the toolbar keeps showing *Connected*, the poll never restarts,
and the user sees a frozen dashboard with no explanation and no way to recover except
Disconnect/Connect.

I confirmed this by patching `dtc.parse_dtcs` to raise `IndexError` on a real `read_dtcs` job:
the exception escaped `step()`. Today's decoders survived 4,000 random inputs each (six decoders,
no exception), so this is latent rather than actively triggered — but it is one OEM payload away
from being a field bug on a tool that meets a new vehicle every day.

**Fix:** wrap the handler call and the `_maybe_poll` / `_maybe_reconnect` calls in `except Exception`,
emit `error` with the traceback summary, and decide policy per site — a job failure should not
drop the link, a poll failure should count toward the failure budget. Also consider
`sys.excepthook`-style logging so a one-in-a-thousand event is diagnosable.

### 2. Job dispatch is `getattr`-based and silent

`engine.py:134` resolves handlers dynamically and returns silently when the name is unknown:

```python
handler = getattr(self, f"_job_{kind}", None)
if handler is None:
    return
```

`ObdWorker` submits kinds as strings (`"read_dtcs"`, `"freeze_all"`, …). A typo anywhere — or a
future rename in one place and not the other — becomes a button that does nothing forever, with
no error. Verified: submitting `"read_dtc"` produced zero events and no user-visible signal. The
class docstring even points at a `_HANDLERS` map that no longer exists.

**Fix:** an explicit `dict[str, Callable]` registry; unknown kinds raise `KeyError` in
development and emit a visible error in production. This also gives one place to attach
per-job metadata (cancellable, needs-connection, timeout).

### 3. Long jobs ignore the stop request

`stop()` enqueues a `"stop"` job (`engine.py:79`), but a running handler finishes first. The
loops in `_job_read_mode06` (`:293`), `_job_read_freeze_all` (`:243`), `_job_read_mode05`, and
`_discover_supported` (`:628`) each issue many 5 s commands and never check `self._stop`.

`MainWindow.closeEvent` calls `self.worker.shutdown(5000)` (`main_window.py:432`) and ignores the
`bool` return, so when the wait times out the `QThread` is destroyed while still running — the
classic Qt abort path, at the exact moment the user expects an orderly exit (and the point where
session auto-save has already happened, so it looks like data loss).

**Fix:** check `self._stop` between iterations inside every multi-command job and abort with a
`"stopped"` status; have `shutdown()` return success, and in `closeEvent` surface a timeout
rather than continuing blindly. Optionally stop auto-saving until the engine is confirmed idle.

### 4. Minor, but cheap: stringly-typed event contract

An event travels as `(kind, args)` through four layers that each duplicate the name list:
engine `_emit`, `ObdWorker` signals + `_EVENT_KINDS` (`worker.py:44`), `ScanRecord.record_event`
branches, and the lambda bridges in `MainWindow._wire_worker`. `ScanRecord`'s `mode08` branch
already contains defensive shape-sniffing (`record.py:69-78`) because the arity drifted. Adding
a signal means touching three files; forgetting one silently drops data from reports.

**Fix:** define the events once (enum + small dataclass with typed payloads), have the worker map
them mechanically, and drop the lambda bridges now that signals are typed.

## P1 — Performance (measured)

### 5. Live graph redraws everything on every point

`LiveGraph.add_point` (`autodiag/ui/widgets/graph.py:116`) does:

```python
self._curves[pid].setData(list(xs), list(ys))   # full copy of up to 2,400 points
self._render_ranges()                           # full y-scan + setXRange/setYRange
```

Measured with 6 graphed series, feeding points as the engine does:

| buffer fill | cost per 6-PID batch |
|---|---|
| first 100 samples | 1.20 ms |
| last 100 samples (2,400/series) | 5.40 ms |

4.5× degradation, and 7.8 s of pure render work for ten minutes of plotting. It scales linearly
with the number of graphed channels, so a user who ticks ten parameters pays ~9 ms per batch plus
a repaint. At the 50 ms poll interval the spin box allows, that alone can eat a fifth of the UI
thread.

**Fix:** keep `xs`/`ys` as preallocated `numpy` arrays (pyqtgraph's native input), append in place,
and decouple data ingestion from painting — a 15–20 Hz `QTimer` that calls `setData` once with
the visible slice and `setXRange` only when the window actually moved. Expect an order of
magnitude rather than a constant factor.

#### Resolution (implemented)

Three changes in `autodiag/ui/widgets/graph.py`: samples append to fixed-capacity `numpy`
columns through an amortised O(1) ring (`_Series`), pyqtgraph receives *only the visible time
slice* as an immutable snapshot, and redraws are coalesced per event-loop turn (a 6-PID poll
burst now redraws once, not six times). `LiveGraph.flush()` renders pending samples immediately
and is called by `set_window`, pause, and export.

Before/after with the same harness (6 series, 250 ms batches, medians, CPython 3.12,
offscreen):

| window | fill | before ms/batch | after ms/batch | gain |
|---|---|---|---|---|
| 120 s | 50 | 1.93 | 0.85 | 2.3× |
| 120 s | 2,400 | 3.00 | 0.86 | 3.5× |
| All | 50 | 1.99 | 0.80 | 2.5× |
| All | 2,400 | 6.53 | 0.87 | 7.5× |

The point of the change is the last column's shape: cost now stays flat as history accumulates
(+1 % for the 2-minute window, +8 % for "All", versus +55 % and +228 % before). Paint time at
full buffer dropped from 6.5 ms to 4.3 ms with the 2-minute window, because only ~480 visible
points are tessellated instead of 2,400. Reproduce with
`QT_QPA_PLATFORM=offscreen python tools/bench_graph.py`.

Absolute milliseconds move ~15 % between runs on a loaded machine; the shape does not. A second
run reported 1.53× → 1.05× growth for the window and 4.05× → 0.99× for "All", i.e. the same
conclusion with noisier denominators.

### 6. 30 ms of dead time before every adapter command

`Elm327Session._drain` (`autodiag/obd/elm327.py:203`) calls `transport.read(4096, timeout=0.03)`
before each write. On a real port `read()` blocks until the timeout when there is nothing to read,
so every command costs a fixed 30 ms. Measured through `Elm327Session` with a transport that models
blocking serial reads: **30.1 ms per `AT` command**, i.e. 12 % of the default 250 ms poll budget,
and a UDS exchange (`AT SH` + `AT CRA` + request + 2 restores) pays it five times (~150 ms).

**Fix:** give `Transport` an optional non-blocking `pending() -> int` (pyserial exposes
`in_waiting`) and drain only when bytes are actually queued; fall back to the timed read for
transports that cannot answer. A no-op fast path is enough — the drain exists for stale prompts,
which are rare.

#### Resolution (implemented)

`Transport.pending()` defaults to `None` ("cannot tell"); `SerialTransport` answers it from
pyserial's `in_waiting` without touching the port, and `Elm327Session._drain` now returns after
one non-blocking check when the buffer is empty. The timed-read loop is unchanged for transports
that cannot report their buffer, so behaviour on exotic backends is exactly as before.

Measured with a port that blocks like pyserial and an ECU with a 20 ms turnaround
(`python tools/bench_serial.py`):

| drain | per command | 5-command exchange | sustained requests/s |
|---|---|---|---|
| reported buffer | 20.11 ms | 100.6 ms | 49.7 |
| timed read (before) | 50.19 ms | 250.9 ms | 19.9 |

The 30 ms difference per command is the drain alone, and the UDS exchange saves exactly
5 × 30 ms. At the default 250 ms poll interval the overhead on a batched PID request falls from
12 % of the budget to ~0.04 %. The fake-backed test suite also shrank from 22.4 s to 10.3 s, because every
command stopped paying 10–30 ms of simulated silence.

#### The loop timer above it

Fixing the drain exposed the next floor. `run_forever` called `step()` with its default 50 ms
queue wait on every iteration, so the engine could not start a poll more often than that: with a
20 ms ECU the ceiling was ~14 samples/s regardless of the configured interval.

`step()` now derives its sleep from the next scheduled poll or reconnect attempt
(`ObdEngine._idle_wait`), and `run_forever` passes `timeout=None`, so an engine with nothing
scheduled parks until a job arrives. A due poll floors the sleep at 1 ms (an interval of 0 must
not spin the CPU) and scheduled sleeps are capped at 1 s (a huge or infinite interval must not
reach `queue.get`). `step(0)` stays non-blocking, which is what the unit tests rely on; the CLI
now passes its remaining scan time instead of a 50 ms slice.

Measured with `python tools/bench_engine.py` (20 ms ECU, two seconds per row):

| poll interval | before samples/s | after samples/s |
|---|---|---|
| 0 (as fast as possible) | 14.0 | 46.0 |
| 50 ms | 14.0 | 20.0 |
| 250 ms (default) | 4.0 | 4.0 |

The default rate was already interval-bound, so this is a fast-polling and multi-command win, not
a change to the 4 Hz dashboard. Idle stop→exit stayed at ~0.1 ms — `stop()` enqueues a job, which
wakes the loop — but an idle connected engine now wakes 4 times a second instead of 20.

### 7. Per-sample work on the UI thread

Three listeners run for every PID value (`main_window.py:222-232`): CSV logging (with
`datetime.now` and a `PID_REGISTRY` lookup), alert evaluation, and the dashboard. The logger
then calls back into `DashboardPanel.set_log_status` **per row** (`live_log.py:110`), re-rendering
a label with a formatted row count up to ~24 times a second. Harmless today, wasteful at 50 ms
intervals with many channels, and it serializes disk I/O with painting.

**Fix:** accumulate log rows and flush on the existing `flush_every` boundary (20 rows) — the
callback already has that counter; format the label from a 250 ms `QTimer`.

### 8. Eager panel construction at startup

All 14 panels are built in `_build_central`. Measured cold start offscreen: `QApplication` +
theme 217 ms, `MainWindow` 187 ms, **404 ms to first paint** — and half of that 187 ms builds
panels the user may never open (UDS alone is 780 lines of widgets, the log viewer builds a
pyqtgraph plot).

**Fix:** keep the dashboard/overview eager and construct the rest on first activation
(`QStackedWidget.setCurrentIndex` hook). ~100 ms is a real win on the low-spec laptops shops
keep in the bay.

## P2 — Report correctness

### 9. Mixed time bases in one document

`build_report` writes `generated_at` with `datetime.now(UTC).isoformat()` but UDS rows with
`datetime.fromtimestamp(timestamp).isoformat(timespec="seconds")` (`export.py:119`) — local
naive time, no offset. Verified: `generated_at: 2026-10-21T12:06:38+00:00` beside
`uds time: 2026-10-21T17:00:00` for the same instant. A report that crosses timezones (shop →
customer → insurer) is ambiguous exactly where the sequence of requests matters.

**Fix:** `datetime.fromtimestamp(ts, UTC).isoformat(timespec="seconds")`; keep local time for
display only.

### 10. CSV formula injection

`report_to_csv` (`export.py:181`) writes values verbatim; work-order fields, DTC descriptions and
NHTSA recall text all reach the file. Verified:

```
work_order,customer,,=cmd|' /C calc'!A0
work_order,phone,,+61400000000
```

Opening a shop's report in Excel runs the payload; `+`-prefixed phone numbers are also coerced to
formulas/numbers. The input is user-authored, so this is low severity, but these files are
explicitly meant to be shared (work order → customer, insurer).

**Fix:** neutralize cells beginning with `= + - @ \t \r` (prefix `'`) at the single `add()` choke
point in `report_to_csv`. One function, one test.

#### Resolution (implemented)

Both findings are fixed in `autodiag/services/export.py`.

**One time base.** `build_report` now writes UDS rows with
`datetime.fromtimestamp(timestamp, UTC).isoformat(timespec="seconds")`, so every stored
timestamp in JSON and CSV is UTC with an explicit offset, and `generated_at` is normalised to UTC
even when a caller passes a naive `datetime`. Local time survives only as presentation: a new
`_display_time` helper renders the HTML/PDF header and the UDS *Time* column in the machine's
zone with the offset attached (`2026-10-22 01:06:52 +0530`), so a printed page still reads as
wall-clock time without becoming ambiguous. Verified on a report generated under
`TZ=Asia/Kolkata`: JSON `generated_at` and every `uds[].time` are `…T19:36:52+00:00` (the same
instant), while the HTML header and the UDS row both render `2026-10-22 01:06:52 +0530`. The live
log already used this convention (UTC, `isoformat(timespec="milliseconds")`), so a saved session
and its report now agree.

**No formula cells.** All four columns go through `_csv_cell` at the single `add()` choke point,
not just `value`: UDS request hex, recall campaign ids and the live-log filename are written by a
human or a remote service and land in the `section`/`key` columns. Cells leading with `= + @`,
tab, CR or LF are prefixed with `'`, the standard CSV-side neutralizer. A leading `-` is only
treated as hostile when the cell is not a plain measurement, so `-12.5 °C` stays numeric and
`-2+3` or `-1+1+cmd|' /C calc'!A0` do not. Verified through the generated artifact (CSV, JSON,
HTML and a PDF rendered by the real `QTextDocument` path):

```
work_order,customer,,'=cmd|' /C calc'!A0
work_order,phone,,'+61400000000
work_order,job,,'@SUM(1+1)
work_order,mileage,,184220
live_data,0F,Intake air temperature,-12.5 °C
```

Seven new tests in `tests/test_export.py` cover the shared time base, naive and off-UTC `now`
normalisation, the local-with-offset display, the fully-neutralized injection sample (plus a sweep
asserting no cell in any column starts with a formula character), and the untouched negative
measurement.

### 11. PDF is not the HTML report

`write_report_pdf` (`ui/pdf.py`) hands `report_to_html` to `QTextDocument`, which implements a
small subset of CSS2: `display:flex` (used for the KPI cards and the two-column adapter/vehicle
block) is ignored, so those sections stack instead of laying out, and `@media print` rules never
apply. The PDF also has no page numbers, header or footer with VIN/date — the things a printed
invoice-style document needs.

**Fix:** a small print-oriented stylesheet (tables + explicit widths, no flex) selected by a
`report_to_html(..., for_print=True)` flag, plus `QTextDocument` page furniture (or a
`QPagedPaintDevice` header/footer pass). Add a snapshot test on a rendered PDF to catch
regressions.

## P3 — Architecture and maintainability

### 12. Three god-objects

| File | Lines | Mixed concerns |
|---|---|---|
| `ui/panels/uds.py` | 780 | layout, licence gating, waiver UX, SGW flow, Mode $08, request history |
| `services/export.py` | 710 | data shaping, CSV, HTML, plus an embedded stylesheet |
| `services/engine.py` | 684 | job registry, polling, batching, reconnect policy, SGW/UDS orchestration |

These are the files where every new feature lands, and each is now hard to review in one pass.
The engine is the one I would split first because it is pure Python and fully tested:
`JobRunner` (dispatch + error policy), `PollScheduler` (batching, failure budget, voltage cadence),
`LinkSupervisor` (connect/reconnect/backoff). `export.py` splits cleanly into
`report.py` (build), `csv.py`, `html.py` (`_HTML_STYLE` moves to its own module or file).
`uds.py` can keep the request box and delegate the SGW + Mode $08 sections to child widgets.

### 13. `ScanRecord.reset()` rebuilds itself through `__dict__`

```python
self.__dict__.update(ScanRecord().__dict__)
```

Works, but bypasses `__init__`, breaks subclasses, and silently keeps any attribute that is not a
dataclass field. Prefer an explicit `reset()` that reassigns fields, or return a new record from
the caller.

### 14. No static types in a heavily typed codebase

Every module is annotated (`from __future__ import annotations`, `Callable`, dataclasses) but no
checker runs, and `uds.py` already carries five `# type: ignore[misc]` where event payloads are
unpacked from `object`. A checker would have caught the event-arity drift behind #4 and the
`payload` unpacking in the engine jobs. Start narrow — `obd/` and `services/` — with
`disallow_untyped_defs` and no `Any` escapes, then expand.

### 15. Stale lint suppressions

`services/nhtsa.py:45,52` carry `# noqa: S310` while `[tool.ruff.lint] select` does not include
`S`. Either enable `flake8-bandit` (worthwhile for a tool that parses hostile serial input and
opens URLs) or drop the suppressions; today they read as the remains of an abandoned security pass.

## P4 — CI, dependencies, process

1. **One Python version.** CI pins 3.13 while `requires-python = ">=3.11"`. A 3.11/3.12 job is
   nearly free and would protect the `datetime.UTC` / `match` / typing floor you advertise.
2. **Unbounded PySide6.** `PySide6>=6.6` with no upper bound, while `tests/conftest.py`
   documents a heap-corrupting bug in 6.12.0 that required a workaround. An upstream release can
   break the suite or the packaged app between two CI runs with no change of yours. Cap `<7`,
   and add a lock file (uv or pip-tools) so CI and the release build resolve identically.
   `cryptography` and `pyqtgraph` deserve upper bounds too.
3. **No coverage gate.** 9.3k test lines deserve a number; `--cov-fail-under` around 85 with the
   UI excluded from the target is a realistic starting point, and coverage diffs on PRs are the
   cheapest regression brake you can add.
4. **Version in two places.** `pyproject.toml:7` and `autodiag/__init__.py:3`, with the release
   workflow regexing pyproject and the app reporting `__version__`. Derive one from the other
   (`importlib.metadata.version("autodiag-pro")` with a source fallback).
5. **README is a feature ledger.** 37 milestone rows and a download/usage/troubleshooting guide in
   one file; it now competes with the app for attention. Move the milestone table to `docs/` and
   keep the README to install → connect → what each panel does.
6. **Local dev environment.** This checkout's `.venv` symlinks to system Python 3.12 while its
   site-packages are 3.13, so `pytest` dies with `No module named '_pytest'`. Not a repo bug, but
   the documented setup silently depends on `python3-venv`/`ensurepip`; a `Makefile` target or a
   `uv sync` line in the README would save an hour for the next contributor.

## Product opportunities (beyond the code)

- **Network transports.** `Transport` is already an abstract byte pipe, so an ELM327-over-Wi-Fi
  (TCP 35000) and an ELM327-BLE adapter are small additions with outsized reach — a large share
  of cheap modern dongles are Wi-Fi/BLE-only, and the current README tells those users to buy a
  different adapter.
- **Longitudinal view.** Sessions already persist everything needed to answer "is this car
  getting better?": add a per-VIN trend (monitor completion, DTC recurrence, freeze-frame deltas)
  on top of `compare.py`, which currently only diffs two sessions.
- **CLI parity.** `compare`, `--pdf`, and a headless `--uds` request would make the tool scriptable
  for fleets; today those live only in Qt widgets.
- **Guidance authoring.** `dtc_guidance.json` is a bundled static file; letting a shop add local
  entries (and share them between machines) turns the advice panel into an actual knowledge base.
- **Licence enforcement is client-side only.** Ed25519 verification is sound, but `FEATURE_TIERS`
  and the panel gates live in the shipped binary; a Workshop tier at $49/mo is one patched byte
  away from free. Either accept that explicitly in the docs or bind the tier to the Store receipt.

## Appendix — how the numbers were produced

Dependencies were installed into `/tmp/adiag-deps` (the repo's `.venv` is unusable on this
machine) and the suite was run with `PYTHONPATH=/tmp/adiag-deps QT_QPA_PLATFORM=offscreen`:

- `pytest -q` → 649 passed, 22.0 s.
- Graph: `LiveGraph` with six active PIDs, `add_point` called 2,400 times per series, timing the
  first and last 100 iterations; `QApplication` offscreen, no `processEvents` inside the loop, so
  the figure is Qt-side work only (real painting costs more).
- Serial: `Elm327Session` over a transport whose `read()` sleeps for its timeout when idle and
  answers instantly when bytes are buffered — 50 × `ATRV` → 30.1 ms/command.
- Startup: `QApplication` + `apply_theme` + `MainWindow(...)`, offscreen, fresh `QSettings` dir.
- Fault injection: `dtc.parse_dtcs` patched to raise on a real `read_dtcs` job against
  `tests/fakes.scripted_connector`; decoder fuzz: 4,000 random strings × 6 response parsers.
