# Microsoft Store submission runbook

AutoDiag Pro is sold as a **paid app with a free trial** on the Microsoft
Store. Licensing, trial enforcement, payments, and updates are all handled by
the Store — the app itself contains no licensing code. After the Store
launch, GitHub Releases no longer carry public binaries (Store-only).

## 1. One-time setup (you — takes a few days the first time)

1. Register as an **individual developer** (free) at
   <https://storedeveloper.microsoft.com> with a Microsoft account:
   - Personal identity verification: government ID + selfie (typically
     approved within 1–2 days, occasionally longer).
   - Note your **Publisher** string (shown as `CN=...`) in
     *Account settings → Publisher identity*.
2. In Partner Center, create the app submission to **reserve the package
   Name** (e.g. `AutoDiagPro_abc123`) — *Apps & games → + New app*.
   The Name is permanent once reserved.
3. In the GitHub repo (*Settings → Secrets and variables → Actions*), add:
   - `MSIX_PUBLISHER` — your exact `CN=...` publisher string
   - `MSIX_PACKAGE_NAME` — the reserved package Name
   - `MSIX_PUBLISHER_DISPLAY` — your display name (e.g. `Jane Doe`)
   Any tag build from then on produces a correctly identified
   `autodiag-msix` artifact. Until the secrets exist, CI still builds the
   package but with a **placeholder identity** (fine for pipeline testing,
   never submit that package).

## 2. Building the .msix

CI (preferred): every tag build runs the `package-msix` job → download the
**autodiag-msix** artifact from the run's page.

Local (Windows, after `pyinstaller --noconfirm autodiag.spec`):

```powershell
pip install pillow
$env:MSIX_PUBLISHER = "CN=..."; $env:MSIX_PACKAGE_NAME = "..."
python packaging/msix/build_msix.py --dist dist\autodiag.exe --out out --pack
```

The package is **unsigned on purpose** — Partner Center signs it with its
own certificate during ingestion. The version is the app version padded to
four parts (`0.22.0` → `0.22.0.0`); each upload must have a higher
four-part version than the previous one (CI takes care of this per tag).

## 3. Listing content (paste-ready draft)

- **Title:** AutoDiag Pro
- **Subtitle:** OBD-II diagnostics for ELM327 adapters
- **Description (short, first line):** Desktop OBD-II scan tool — live
  data, diagnostic trouble codes, readiness monitors, UDS requests and
  professional reports, entirely offline.
- **Feature bullets:**
  - Live dashboard with over 140 J1979 PIDs, graphs and trip max/min
  - Freeze-frame data, readiness (monitors) and Mode $06 test results
  - Generic + manufacturer DTC lookup with a 10,000+ code dictionary
  - UDS (ISO 14229) requests for advanced diagnostics — with safety
    waiver for write services
  - Mode $08 bi-directional active tests (EVAP, EGR, O2 sensor) behind the
    write waiver — outcomes saved in session history and exports
  - Curated UDS preset library ($2F/$31) for common bi-directional controls
  - Security-gateway (SGW) unlock relay: $27 seed/key on the gateway module
    (Workshop tier) — Ford seed-key algorithms built in
  - Scan history, HTML/PDF/CSV reports and customer work orders — sessions
    auto-save and survive crashes (restored on next launch)
  - Local repair guidance — likely causes, first checks and freeze-frame context
    for stored codes (offline heuristics)
  - VIN decode and open safety-recall lookup via official NHTSA services
    (opt-in, on press)
  - Works fully offline — no accounts, no telemetry; the update check and
    NHTSA lookup only run when you press their buttons
- **Category:** Utilities & tools (secondary: System utilities)
- **System requirements:** Windows 10 version 1809 (build 17763) or later,
  x64; ELM327-compatible USB or Bluetooth SPP adapter (not included).
- **What's new (per release):** copy the release notes from the matching
  GitHub release/tag.

## 4. Artifacts to attach in Partner Center

- **Screenshots** (required, min 1366×768, 16:9 recommended): capture from
  the Windows build — dashboard, live graph, DTC view, readiness, UDS panel,
  history, report export. 7–8 shots.
- **Product icon** (1024×1024): reuse the gauge artwork at full size
  (`python packaging/make_icon.py` writes the 1024 canvas; save a scaled
  PNG), or use the package logos auto-generated by `make_msix_assets.py`.
- Logos/splash inside the .msix are already generated — Partner Center
  shows them automatically.
- **Trailers/videos:** optional, skip for v1.

## 5. Pricing (freemium — decided at M30)

- Listing price: **Free** — the base tier (generic OBD-II read/clear, live
  gauges, CSV/HTML export) is the acquisition funnel.
- Pro / Workshop tiers unlock via signed licence keys
  (`packaging/make_license.py`; source `key` for direct sales, `store` for
  Store-linked purchases). The in-app **Upgrade in Store…** button deep-links
  to the listing (`ms-windows-store://pdp/?ProductId=…`) once the Product ID
  is entered in Settings — purchases still arrive as licence keys.
- Microsoft in-app purchase wiring (IAP) may follow later; the licence-key
  flow is the v1 monetization path and needs no Store billing.
- The earlier "paid app + trial" plan is **superseded**; if the submission
  is created before M36, still publish it as Free with a "Pro upgrade
  coming" note rather than charging for the base app.

## 6. Age rating & compliance

- Age rating questionnaire: no user interaction between users, no ads, no
  in-app purchases, no offensive content → ratings low (Everyone).
- **Privacy policy URL** (required): host `docs/privacy-policy.md`
  (e.g. GitHub Pages: `https://<user>.github.io/autodiag-pro/privacy`) and
  paste the URL in the submission.
- **Support URL** (required): repo Issues page or your support email.
- Certification notes to preempt questions:
  - Full-trust desktop app (Win32/PySide6); uses serial ports (COM) to talk
    to ELM327-class OBD-II adapters; the adapter is **not included**.
  - No network use beyond an optional GitHub update check.
  - Not affiliated with any vehicle OEM.

## 7. Submit and certify

1. *Development → Product reservation/Identity* matches the MSIX exactly
   (Name + Publisher typos are the #1 ingestion failure — CI reads both
   from secrets, so they match by construction).
2. Use **Private flighting / internal testing** first: assign yourself a
   test license, install, connect an adapter, buy-and-refund path check.
3. Submit for certification — first submission typically takes 3–10 days.
   If Microsoft asks about serial-port access or full-trust, point them at
   the certification notes above.

## 8. Launch day (Store-only transition)

One small commit to flip the repo:

1. `.github/workflows/release.yml`: remove the `softprops/action-gh-release`
   step (or the whole `release` job) so tags no longer publish binaries —
   keep the builds as private artifacts.
2. `README.md`: Download section → Microsoft Store badge/link; note that
   updates ship through the Store.
3. The in-app "Check for updates" feature keeps working and simply reports
   up-to-date once GitHub stops publishing releases.

## 9. Ongoing releases

Every Store release after launch:

1. Tag as usual (CI builds exe + .msix artifacts).
2. Partner Center → the app → *Updates → Package* → upload the new
   `autodiag-msix` .msix.
3. Update *What's new* from the release notes; submit. The Store handles
   delivery and auto-update to customers.

## 10. Launch checklist (M36)

App-side readiness is done — `python packaging/store_check.py` passes on a
tagged release (CI runs it in the `package-msix` job). What remains is the
Partner Center registration (a user action; individual account, free):

1. Register at [partner.microsoft.com](https://partner.microsoft.com) with the
   individual account; reserve the name **AutoDiag Pro**.
2. Create the submission from §3; paste the listing draft, upload
   screenshots/icon, set the category and system requirements (§4).
3. Set the **Product ID** (visible in the submission) in the app:
   *Settings → Store Product ID* — this activates the in-app
   **Upgrade in Store…** deep link.
4. Fill the privacy policy URL (§6) and support URL; answer the age-rating
   questionnaire.
5. Price: **Free**; tiers sell as licence keys (§5) — no IAP setup needed.
6. Submit for certification; on approval, set the listing live.
7. Tag `v0.23.0` (or the next version) — CI builds the .msix; upload it in
   Partner Center (§9) and paste the release notes into *What's new*.

After launch, GitHub releases stop being the distribution channel (§8) —
the Store version is the only public one.
